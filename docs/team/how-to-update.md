# 团队协作指南

## 协作模型

- 文档站点源码在仓库 `main` 分支，GitHub Pages **自动部署**：合并到 `main` 即自动更新站点
- 所有变更通过 **PR** 提交，由项目负责人（或互相 review）合并
- 看板页面的「更新记录」由构建自动汇总，无需手动维护列表

## 提交进度的三步法

1. **新增进度记录**：在 `docs/progress/updates/` 下新建文件，命名 `YYYY-MM-DD-简短标题.md`
2. **更新看板**：修改 `docs/progress/index.md` 中对应工作流的状态、日期、负责人
3. **提交 PR**：使用「进度更新」PR 模板，合并后站点自动更新

## 进度记录模板

```md
---
title: 本次更新标题
date: 2026-10-14
author: 张三
workstream: P4 端内支付
status: 进行中
---

一句话摘要（看板列表会展示这一段）。

<!-- more -->

## 本期进展

- 完成事项 A
- 完成事项 B

## 下一步计划

- 计划事项 A

## 风险 / 阻塞

- 阻塞原因与需要的支持
```

::: tip 摘要约定
`<!-- more -->` 之前的第一段是一句话摘要，会出现在看板「更新记录」列表中；`<!-- more -->` 之后是完整内容。
:::

## frontmatter 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 更新标题 |
| `date` | 是 | 日期 `YYYY-MM-DD`，用于排序（新记录日期越大排越前） |
| `author` | 是 | 负责人姓名 |
| `workstream` | 是 | 所属工作流：商务合规 / P0~P7 / 全局 |
| `status` | 是 | 未开始 / 进行中 / 已完成 / 阻塞 |

## 看板状态定义

| 状态 | 含义 | 要求 |
| --- | --- | --- |
| 未开始 | 尚未启动 | — |
| 进行中 | 正在执行 | 每周至少提交一次进度 |
| 已完成 | 交付物达成 | 写明交付结论 |
| 阻塞 | 因外部原因暂停 | 必须写明阻塞原因与需要的支持 |

## 提交功能 / 需求建议

- 功能建议：提交 **issue**，标签 `enhancement`，描述场景与预期
- 文档勘误：直接提 PR
- 进度更新频率建议：每个工作流至少每周一次；里程碑变化随时更新

## 常见问题

**Q：我不熟悉 Git / PR 怎么办？**
A：最简单的方式是在 GitHub 网页端操作：打开 `docs/progress/updates/` 目录 → Add file → Create new file，粘贴模板内容填写，提交时选择「Create a new branch and start a pull request」，负责人会帮你 review 合并。

**Q：更新记录列表是自动生成的吗？**
A：是。只要在 `docs/progress/updates/` 下新增符合模板的 md 文件，构建时会自动收集并倒序展示，无需手动修改列表。

**Q：看板表格和更新记录会冲突吗？**
A：看板表格是「当前状态快照」，需要手动维护；更新记录是「历史流水」，自动汇总。两者需保持一致：更新看板状态的同时提交对应进度记录。
