# 完整订阅接入：套餐、订单、官方测试与履约实施计划

> 执行方式：在当前功能分支继续，服务端与用户界面按明确文件范围并行；每项先复现失败，再实现和复核。不创建另一套用户身份或 Beans 订阅。

**总目标不变：** Aurora 在日本正式可订阅，正确处理开通、续费、取消、到期、欠费、退款及恢复购买，并经官方环境和真机验证。官方测试入口不是这个目标的完成标志。

**架构：** 复用已有 TikTok 订阅六接口适配器与业务登录。正式订阅金额是平台价格字符串和币种，不能放进现有“整数 Beans + 固定天数”的测试 VIP 订单。增加独立的套餐报价与订阅操作记录，通过原始已验签通知和后续真实协议完成履约；原有单集／整剧和本地测试 VIP 保持兼容。

**技术：** Vue 3、TypeScript、Express、SQLite、Vitest、Playwright。

## 本阶段接口

所有路径位于 `/api`，使用现有业务会话。普通用户只能读取自己的记录；管理员不伪装为观看用户。

| 接口 | 行为 |
| --- | --- |
| `GET /subscriptions` | 本地配置状态及当前未完成操作，不自动外发 |
| `POST /subscriptions/quotes` | 仅接受 `devicePlatform`，查询当前用户订阅及服务端允许的档位，保存 5 分钟报价 |
| `POST /subscriptions/operations` | 接受 `action / quoteId / tierId / requestId`；重新核对平台状态与报价，再创建或重新启用官方测试订阅 |
| `GET /subscriptions/operations/:id` | 读取当前用户原操作；刷新不重建、不开 SDK |
| `POST /subscriptions/operations/:id/start` | 空请求体，一次性领取对应 SDK 指令；重复调用不能再次打开付款流程 |
| `POST /subscriptions/operations/:id/check` | 空请求体，查询原交易并保留观察结果；不当付款通知或发放会员 |

报价和操作均绑定应用、环境、业务用户及平台身份。操作未知时保留原编号；重新登录仍可查询。创建回执在响应丢失或用户退出后仍保存，不交给失效会话。开通与重新启用分别调用已有 SDK 方法。

## 文件范围与验收

- 服务端：`server/subscription-workflow.ts`、`server/subscription-config.ts`；通过现有 `commerce.ts` 接入，配置类型及建表追加。
- 协议：`shared/subscriptions.ts`。不修改现有 `Order.amount` 含义，不挪用单次购买的 `settleOrder` 发订阅权益。
- 用户端：`src/views/Subscriptions.vue`、路由和 Profile 的正式 VIP 入口；复用 `api`、用户会话和 `ttSDK`，不新增持久化明文 token。
- 测试：真实 HTTP 的报价／操作／隔离／重启；真实 Vue 的官方测试 SDK 调用、未知状态恢复、取消不假成功及错误恢复。
- 原数据库只新增表，不重置用户、作品、订单和权益；备份不带任何新增平台凭据。
- 当前权益观察独立于付款账本：关闭销售不抹掉已买会员；网络失败不能当“未订阅”，且不阻断已有单集／整剧购买权益。收到已验签订阅通知后使观察过期，强制重新核对，不猜通知内部字段撤销整份会员。
- 每次消费平台响应后重新核对会话、应用、环境和用户身份；跨账号迟到响应不显示。
- 正式环境的旧 `POST /orders kind=vip` 在写订单前明确拒绝，不能留下冒充 Beans 商品的失败订单。
- 每阶段做独立检查，最后再运行 `test:all`、前后台／服务构建、Minis 包校验和文档构建。
