# 订阅通知不再被静默丢弃

**2026-10-15：本轮完成的是正式通知入口的可靠收件和后台查询，不是完整订阅上线验收。** 自动续费、取消、到期、重新启用、退款和恢复购买仍保留在总目标中，不因本页功能完成而删减。

## 修复了什么

此前支付回调只处理单次 Beans 交易。即使收到有效的订阅通知，也会返回 `200 { ignored: true }`，没有保存通知，无法在后续订阅接入时核对。

现在：

1. 沿用原始请求体和 TikTok 签名验证，核实属于当前应用。
2. 核查官方通用事件外层，不猜订阅内容字段或期间单位。
3. 将原始字节和签名加密保存到数据库；落库和审计记录一起提交。
4. 只有事务成功后才返回“已接收、待协议处理”。密钥缺失或存储失败返回错误，不假确认。
5. 管理员在 **订单 → 订阅通知收件箱** 查看脱敏记录，可刷新和翻页。

像收到挂号信：先核实来源、登记并妥善保存，而不是签收后把信扔掉；但登记收到不能代替确认信中那笔交易。

## 处理范围

已识别官方指南点名的五类事件：

```text
minis.subscription.create
minis.subscription.renew
minis.subscription.onhold
minis.subscription.expire
minis.subscription.reactivate
```

同一订阅命名空间下的新事件也保存，但明确标为“新事件类型，待核对官方协议”，不自行推断行为。

本地处理状态 `pending_contract` 表示待订阅协议解码，**不是 TikTok 官方订阅状态**。此模块不创建订单、不发会员、不增加天数、不退款、不调用外部建单接口。

## 数据和权限

- `subscription_webhook_receipts` 是追加的新表，跟随当前环境数据库持久化，不清空旧表。
- 每次投递保留独立记录。相同原文的指纹相同，但投递次数不能当作扣款或续费次数。
- 使用 AES-256-GCM 加密完整原始请求体和签名。应用、接收环境、事件类型和原文指纹参与校验，不能跨应用挪用密文。
- 原始平台用户编号不出现在后台列表；只有已有的、按应用隔离的 TikTok 用户身份匹配时才关联内部用户 ID。
- 查询只返回当前应用和当前接收环境的记录。换应用配置不会混入另一应用的历史通知。
- 后台只显示时间、事件类型、内部用户关联、指纹、重复投递次数和待处理状态，不返回原始载荷、签名、令牌或密文。
- 未登录和普通用户不能查询；没有“模拟履约”“标记已付”“删除通知”等写接口。

## 不混淆两种环境

列表中的“接收服务：本地／预发布／正式”描述这台业务服务的配置。

“来源环境待核实”表示订阅通知内部的正式／测试环境字段尚未按最终契约完成解码。不会因为请求到了正式服务器，就认定它是真实付费；也不会把缺失字段默认成 `false`。

因此，当前收件可以记录待查证通知，但不会给任何环境发放订阅权益。

## 前端订阅桥接准备

本轮还补充了官方 `reactivateSubscription(callback, options)` 适配，并按操作区分取消码：

- 开通订阅的 `116601`，即使 SDK 错误文案不是英文，也显示用户取消，而不是笼统故障。
- 重新启用自动续费的 `118601`，不解释成“已取消合同”或“恢复购买”。
- 重新启用仍要求服务器交易号；能力缺失时不会退回新建订阅，不会重复发起。
- 预览环境仍禁止真实调用；超时后不自动重试，晚到回调不改变已经结束的请求。

前端 6 个测试文件、145 项单测通过，前端类型检查和构建通过。**这只是 SDK 适配，不是已向消费者开放重新启用，更不是已经完成真实订阅生命周期。**

## 2026-10-16 追加：管理员核对平台当前订阅

在 **用户 → TikTok 用户 → 核对订阅** 中，管理员现在可以通过后端查询该用户的真实平台适配器。平台身份只从服务器已保存的授权取得，不接受网页传入 access token 或另一个用户身份。

- 展示合同编号、档位、最近交易、当前权益标志、续费标志和明确的正式／测试／未知来源。
- `is_renewal_normal=false` 不直接显示为“已取消”；可能还有欠费等情况，界面说明需要进一步核对。
- 平台原始时间仍保留整数原文，不猜单位、不冒充到期日期或会员天数。
- 查询使用按应用、环境和用户身份隔离的 30 秒只读缓存，合并并发请求，显示实际查询时间与缓存标记。
- 管理员在请求途中退出、目标用户身份或环境改变时，不返回旧查询结果。
- 查询失败不是“无订阅”；也不生成付款、退款、续期或会员发放记录。

新增接口：

```text
POST /api/admin/users/:id/subscriptions/query
请求体：{}
响应标记：isFulfillmentProof: false
```

本次追加的 11 项服务端查询测试、2 条新浏览器路径通过。随后完整后台回归 **25 项通过，0 失败、0 跳过**。

独立审查发现订阅通知区屏蔽 401 后会保留旧会话记录；相同问题也存在于追回通知区。两处均改为使用统一的会话失效清屏流程，并先复现、再修复两条浏览器回归。普通 503 错误仍只在对应区块提示，不会强制退出后台。

首次全后台回归还发现旧测试未提供新增的媒资只读接口，以及旧测试把“通知暂不可用”写成 401。已补齐与真实接口一致的测试数据，并将服务不可用改为 503；真正的 401 使用独立退出清屏测试，未通过放松鉴权解决。
