# Aurora 云部署：日本首发选东京，不先买三套

更新：**2026-10-18（北京时间）**。目标是 **Aurora Drama，日本首发**；韩国和东南亚以后按实际运营计划扩展。本页已替换早期“订阅／云上传仍未开发”的旧清单，历史价格和当时观察继续保留在对应进度记录中。

**当前没有已购业务主机、正式域名或云端生产服务。** BytePlus VOD 已开通，私有视频空间已建；上传授权实测仍被拒绝，见 [023 当前交接](/progress/updates/2026-10-18-023-domain-region-iam-readiness)。不要重复绑卡、开通 VOD 或创建同名空间，也不要把本地可运行当作已经上线。

## 1. 香港还是日本：优先东京

日本是首发市场，建议先让 **API 与数据库位于东京同一套业务环境**。AWS 官方建议按主要用户所在地选区；这里是部署建议，并非已经跑过日本、韩国和东南亚各运营商的真实延迟测试。

业务主机和视频云不必同厂商：

```text
日本用户的 TikTok Minis
  ├─ HTTPS API → 东京业务主机
  │                ├─ 用户身份与会话
  │                ├─ 订单、订阅、观看权益
  │                └─ 片单、运营后台与初期数据库
  └─ 官方播放器 → 平台媒体服务／视频分发

运营后台
  ├─ API 获取短期上传权限
  └─ 官方上传 SDK → BytePlus 私有视频空间
                     → 平台登记、审核、发布后才可供用户播放
```

可以把业务主机理解为“收银台和账本”，视频服务是“片库和放映设备”。不因为影片多就先买 GPU，也不让普通业务主机替所有用户中转视频。

**BytePlus ECS 的官方公开地区表本轮仍未列东京。** 已列出的地区是北京、上海、广州、香港、柔佛和雅加达；VOD 地区、CDN 覆盖和 ECS 可购买地区不是同一份名单。东京业务主机需使用团队已有或已完成开户的其他云账号。

如果团队要求主机也只能用 BytePlus，可以考虑香港，但应先验收日本实际网络。不能为了省一次账号登录，悄悄把首发方案改成香港。

## 2. 起步规格与费用

2026-10-18 读取 AWS Lightsail 官方价格及地区说明。下面均为 **Linux、包含公网 IPv4 的公开套餐参考**，东京在其支持地区中；不是已下单或本账号库存承诺。

| 方案 | 配置 | 公开月价 | 适用范围 |
| --- | --- | --- | --- |
| 低成本联调候选 | 2 vCPU／4 GB／80 GB SSD | 24 美元 | 内部联调，实际容量未测 |
| 本轮推荐起步候选 | 2 vCPU／8 GB／160 GB SSD | 44 美元 | 为服务、后台、数据库和更新预留余量 |
| 后续更大规格 | 4 vCPU／16 GB／320 GB SSD | 84 美元 | 有负载数据后再决定，不先买 |

- Lightsail 有 CPU 基线和突发容量机制，不能把它的 vCPU 数直接等同于普通 ECS 的持续满负载性能。
- 独立备份、快照、额外流量和税费等，按实际选项与合同另计；套餐流量不是无限量。
- **起步业务服务可先按约 50–70 美元／月规划预算**，这是选择 44 美元档后的预算建议，不是含税成交报价；**不含 BytePlus 视频费用、版权、投放、付费客服或后续高可用数据库**。
- 当前没有实际云机上的压测，不能承诺这台机器可以承载多少日活或同时在线用户。

## 3. 本项目已有什么，不能重复开发什么

当前源码已有：

- 用户身份、会话、账户隔离、片库、收藏及续看。
- CMS 剧集、封面、字幕、定价、发布／下架管理。
- BytePlus 浏览器直传、服务端归属核验、失败恢复、草稿导入及平台登记流程。
- 单次订单核对、通知验签、权益发放、退款与撤销。
- 订阅通知、各期账本、续费、退款隔离、会员恢复和解约说明。
- 单机 Nginx／systemd 模板、可信代理限制、环境启动检查及一致性备份／恢复工具。

这些是**已经实现、需要真实部署和平台验收的代码**，不是“生产配置都已填好”。本地自动回归所使用的 SDK／云服务替身，也不等于官方 Sandbox 或真钱交易。

## 4. 真正需要部署的东西

TikTok 只接收 Minis 前端包，**不会替项目运行 Node.js 后端、订单数据库或运营后台**。

### 主机基础

1. 选择一台实际可购买的东京 Linux 主机；建议 Ubuntu 24.04 LTS、x86_64。
2. 安装项目支持的 Node.js 22.x（至少 22.13）或 24.x，固定版本，并在目标 Linux 上跑构建和检查。
3. 部署私有应用代码，不把服务端、环境文件或数据库作为 Minis 前端包上传。
4. 使用专用非登录服务用户；持久数据放 `/var/lib/aurora-drama`，与版本目录分离。
5. 公网只暴露必要的 HTTPS／证书验证端口，管理用 SSH 限制到负责人的可信来源；不能开放数据库或 Node 内部端口。

### HTTPS 与进程

仓库提供的 `deploy/aurora-drama.service` 和 `deploy/nginx.conf` 对应一个明确拓扑：

```text
公网请求 → 本机 Nginx HTTPS → 127.0.0.1:5316 → 应用
```

- 反代会覆盖而不是追加不可信的转发头。
- 服务进程固定监听本机地址，只信任指定的本机反代来源。
- `.env.production` 放在服务配置位置，root 管理、仅服务组可读；不能放进静态资源目录。
- 必须把模板里的占位域名替换成**已经注册、可控、完成 DNS 的实际域名**，签发证书后执行 `nginx -t`。
- 这不是 CDN 多层反代模板。若增加其他代理，须重新确认可信来源和会话／限流测试，不能直接信任所有 `X-Forwarded-For`。

### 真实配置

| 配置 | 要求 |
| --- | --- |
| `.env.staging`／`.env.production` | 分别配置，不能用一份测试数据库承载正式订单 |
| `TIKTOK_CLIENT_KEY`／`TIKTOK_CLIENT_SECRET` | Aurora 的真实配对凭据；开发者登录密码不是 Client Secret |
| `TOKEN_ENCRYPTION_KEY` | 独立随机密钥，进入受控备份；不写前端或公开 Git |
| 管理员账号 | 部署时创建独立凭据，不把本地示范账号当生产管理员 |
| `DRAMA_ALLOWED_ORIGINS` | 实际 HTTPS 页面来源，精确列举，不用通配符 |
| BytePlus 配置 | 真实账号、空间、region、角色、VOD SDK App ID 与专用后端密钥全部就绪后再启用 |
| 平台媒体配置 | 可被平台访问的短期封面导出来源、实际确认的日语枚举与平台媒资绑定 |
| `VITE_API_BASE` | 已部署的 HTTPS API 地址；重新构建 Minis 前端才能生效 |
| 支付与订阅 | 在官方环境验收前维持默认关闭，不能靠改开关替代开通、商品和通知配置 |

当前预发布与生产真实环境文件均尚不存在，启动检查返回缺少文件。这个结果应当保留为未就绪，不能填写看起来像密钥的测试字符串来制造通过。

## 5. 数据与备份

当前数据库是 **SQLite**，不是可随意横向复制的多地区数据库。初期单机可以用于联调与小范围起步，但有单机故障停服风险，不能宣称高可用。

- 使用已有一致性备份工具，不能只复制正在使用的 `.sqlite` 单文件而忽略 WAL。
- 备份必须再存到**独立的私有存储**，不是只留在这台机器的另一个目录。
- 保存必要的加密密钥和恢复说明，限制访问，并实际恢复到空目录验证登录、订单与权益。
- 收费上线前明确可接受的数据丢失和恢复时间，完成备份告警及恢复演练。
- 若后续需要多节点持续可用，先完成共享数据库／存储改造，再购买双节点与负载均衡。当前代码不能仅把连接串改成 PostgreSQL 就完成迁移。

详见[备份恢复手册](/guide/backup-restore)。

## 6. 视频与 IAM 的独立验收

已有 BytePlus VOD 私有空间不需要随 API 主机迁往东京。视频分发、存储、转码及播放器相关费用单独按合同和实际使用量计费，不包含在业务主机月价中。

当前官方 STS 代入请求返回 `AccessDenied`，尚不能签发上传权限。负责人完成人机验证后，由开发正常录入、回查限定空间的策略和角色；不要为尽快成功而授予管理员全权限。

已准备自生成的 5 秒竖屏测试素材，可用于低风险私有联调。实际验收顺序：

1. 短期授权成功，长期密钥不离开后端。
2. 浏览器 SDK 将测试文件直接上传 BytePlus。
3. 服务端确认目标空间、文件大小／格式和未公开状态。
4. TikTok 绑定账号可查询到相同视频。
5. 运营后台完成草稿登记、审核及正式播放器验证。

测试素材不是商业日本片源。正式内容的版权、字幕、可售地区和定价仍需运营提供。详见[云上传手册](/guide/cloud-upload)。
