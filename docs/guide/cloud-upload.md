# 后台直接上传视频云

本功能服务于 **Aurora Drama（`7670022867891177493`）日本首发**。它把“选择本机 MP4 → 云端传输 → 服务端核验 → 可恢复任务记录”接入现有后台。

**云端文件核验完成，不等于 TikTok 剧集已经创建、关联、审核或上架。** 核验完成后，现在可以明确点击“导入为草稿单集”，将视频登记到本地后台，继续编辑标题和字幕。TikTok 云端剧集登记及[已有平台剧目的媒资工作流](/guide/platform-media-workflow)仍分开处理；本页面不会自动发布内容。

## 1. 运营怎么使用

打开运营后台的 **上传素材**：

1. 在上方选择一个已确认版权的草稿剧目。
2. 上半区仍是原来的**本地上传**，文件保存在业务服务器，用于本地业务验证。
3. 下半区是新增的**云端视频上传**。先看空间、region 和文件上限；没有配置时显示具体原因，不显示假成功。
4. 选择一个或多个 MP4。系统按文件名数字排序，接着已有集号排列；开始前核对并修改集数、标题。
5. 勾选顺序确认，点击“开始云端上传”。同一批逐个传，不会让多个大文件挤占连接。
6. 可在当前页面暂停、继续或取消。切换后台导航不会卸载上传区；退出账号或关闭页面会停止本页操作，退出时有上传确认。
7. SDK 报告 100% 后，页面仍显示待核验。服务器核对 BytePlus 和 TikTok 结果，满足条件才显示“云端已核验 · 未关联 / 未上线”。
8. 核验失败点击“重试核验”，只查原任务的 VID，不再次上传文件。
9. 核验通过后点击“导入为草稿单集”。点击就是确认，不额外弹窗；后端只使用已核验的 VID、时长、集号和标题，浏览器不能替换这些字段。
10. 回到“剧目管理 → 单集与字幕”，可编辑导入的单集。此时显示“云端视频 · 待平台登记”，没有 TikTok `episode_id` 就不会冒充平台可播放。
11. 使用新增的[云端剧目登记面板](/guide/platform-registration)，将保存的封面、标题与核验视频登记成平台草稿，再进入既有审核流程。真实日语配置和云端验收仍需完成。

刷新后，服务端保存的任务仍在；已有 VID 可继续核验。**没有原 File 和分片会话的任务不能跨页续传。** 页面会显示中断／待核对，不能把一条数据库记录说成恢复了传输。

管理员的任务互相隔离，只能在当前账号下继续。任务保存不是云端文件管理控制台；取消不会删除已上传视频，也不会立即撤销已经签发的临时权限。

### 导入、重试和后续修改

- 同一任务只导入一次。重复点击或响应丢失后重试，返回原来的本地单集，不再创建、不多加版本。
- 导入会使旧的平台同步证据失效；后续同步必须确认平台同集号的 VID 与已导入视频一致，不能只凭集号覆盖成另一部片。
- 单集后来移到其他集号或被删除，空出的集号可补传。任务保留最初上传目标和导入历史，不改写历史来释放集号。
- 删除后的旧任务显示“原导入单集已删除”，重试导入不会将它悄悄重建；取消旧记录也不会删除云文件。
- 列表通过固定游标读取后续页，不再静默截断于 100 条。跨页校验管理员身份；另一标签页切换账号后，原页面刷新会清除旧任务和上传会话。

## 2. 服务器和浏览器各做什么

```text
管理员选择 MP4
  → 业务服务器创建持久任务，固定剧目、集数、空间与当前应用
  → 服务器通过官方 STS SDK 取得限定空间的短期上传权限
  → 浏览器官方上传 SDK 直接发送文件到 BytePlus
  → 浏览器向业务服务器提交候选 VID
  → 服务器查询 BytePlus，核对任务标记、空间、视频字节数和格式
  → 服务器查询 TikTok，确认当前绑定账号能查询到这个 VID
  → 保存已核验的任务记录，等待后续剧集创建／关联
  → 管理员明确点击导入，创建本地草稿单集
  → 后续完成 TikTok 剧集登记、审核和上架
```

视频字节不经过业务 ECS 的本地文件接口。业务 API 传输的是任务、临时授权和核验结果，不提供公开原片下载 URL。

浏览器使用锁定的 `@byteplus/uploader@1.1.3`，按需加载，只进入管理端，不进入 Minis 用户包。服务端使用官方 `@byteplus/sts@1.0.3` 与 `@byteplus/sdk-core@1.0.2`，没有重写签名算法。

## 3. 团队需要配置哪些信息

先在目标 App 的行业解决方案中确认媒体资产管理状态。**2026-10-18 最新进展：VOD 和私有空间已有，但官方 STS 真实代入请求返回 `AccessDenied`，尚未取得上传权限；控制台新登录会话需要负责人完成人机验证。** 负责人无需自己编写 IAM 策略，由开发继续录入、回查并测试。后台上传角色／策略、VOD SDK App ID 和 TikTok 绑定仍未完成，不能把空间创建当作真实上传已通过。当前状态以 [023 当前交接](/progress/updates/2026-10-18-023-domain-region-iam-readiness)为准；空间及 SDK App ID 路径见 [022](/progress/updates/2026-10-18-022-video-space-web-team-id)，更早观察见 [021](/progress/updates/2026-10-17-021-cloud-activation)、[013](/progress/updates/2026-10-16-013-cloud-upload)和[014](/progress/updates/2026-10-16-014-byteplus-readiness)。企业认证／合作合同需单独核实，不由绑卡或 VOD 可用替代。

在运行后端的服务器安全环境中配置，不要粘贴到聊天或提交 Git：

| 环境变量 | 用途 |
| --- | --- |
| `BYTEPLUS_ACCOUNT_ID` | 已与目标 TikTok 主体绑定的 BytePlus 账号编号 |
| `BYTEPLUS_SPACE_NAME` | 专用视频空间名称 |
| `BYTEPLUS_VOD_REGION` | 实际空间 region；当前支持 `ap-singapore-1` 或 `ap-southeast-1` |
| `BYTEPLUS_VOD_APP_ID` | VOD 的数值 appId，不是 TikTok Client Key 或 App ID |
| `BYTEPLUS_STS_REGION` | 当前接入固定为 `ap-southeast-1` |
| `BYTEPLUS_UPLOAD_ROLE_TRN` | 同账号的专用上传角色 `trn:iam::<账号>:role/<角色>` |
| `BYTEPLUS_ACCESS_KEY_ID` / `BYTEPLUS_SECRET_ACCESS_KEY` | 专用后端签发者；仅后端持有 |
| `BYTEPLUS_UPLOAD_MAX_BYTES` | 默认 `209715200`（200 MiB），与本地上传上限分开 |
| `TIKTOK_CLIENT_KEY` / `TIKTOK_CLIENT_SECRET` | Aurora 配对的服务端身份，供 queryVideo 核实 |

全部云凭据留空时，旧业务继续运行，云上传明确不可用；部分填写或格式错误时启动拒绝，不偷偷选另一个空间。

### 最小权限与原片保护

- 签发者只能代入指定角色，另具备所需的 `vod:GetMediaInfos` 只读核验权限。
- 临时上传权限只含目标空间的 `vod:ApplyUploadInfo` 和 `vod:CommitUploadInfo`。
- 角色信任关系与空间 TRN 必须由 BytePlus 管理员配置，不能因为已经绑定 TikTok 就假定我们后端也有上传权限。
- **上传前关闭该空间的自动发布，并核实原片访问控制。** 本功能不修改整个空间策略；核验时只接受 `Unpublished`，但上传后才发现错误配置不能撤回已经发生的公开访问。
- 上传角色按空间授权，不是云端强制的一集一文件或字节配额。页面的文件上限不能当成 IAM 限额。
- 900 秒临时权限不意味着分片上传 Auth、SessionKey 也恰好 900 秒失效；真实有效期和长时间暂停须云端联调。

当前上限可配置至 20,000,000,000 字节，但**没有验证真实 20 GB 上传**。首发保持默认小文件试点，再分别验收大文件、弱网、跨临时凭据过期和合并阶段。

## 4. 什么时候算“核验通过”

服务器同时要求：

1. 当前管理员仍有有效 Cookie 会话，任务仍属于原账号。
2. 剧目仍可编辑、版权确认仍有效、目标集数未被别人创建。
3. App、环境、BytePlus 账号、空间、region 和角色仍与创建时一致。
4. BytePlus 只有唯一匹配 VID；空间与服务器选择一致。
5. 云端媒体标题为此任务的服务器生成标记，不按浏览器自报标题认领视频。
6. 实际源文件字节数匹配、格式为 MP4、类型为 video、有有效时长，发布状态为 Unpublished。
7. TikTok `queryVideo` 返回同一 VID 且 `upload_status=2`。

`candidate_vid` 只是线索，可以保留作失败重试。只有 BytePlus 确认归属后才写入唯一 `claimed_vid`，防止一个错误任务先提交别人的 VID 后，把那个正确视频永久占住。

TikTok 尚未可见时显示等待，不撤销已核实的云端归属，也不重复上传。若某个请求超过本地处理租约或服务重启，保留任务并退回可核验状态，不重放外部写入。

## 5. 凭据与错误处理

- 长期密钥、TikTok token 不返回浏览器。
- 临时上传凭据只出现在权限接口响应和 SDK 实例内存，不入任务表、审计日志、Pinia、localStorage 或 sessionStorage。
- SDK 的持久任务缓存与调试日志关闭。同页续传保留内存，不靠把凭据写入浏览器磁盘恢复。
- 云接口固定目标地址、10 秒超时、限制响应体大小、禁止重定向和自动重试。
- 第三方原始错误可能包含签名请求，后端只返回固定说明，不携带原响应、请求对象或错误 cause。
- 401 仍触发统一后台清屏；普通云服务暂不可用显示重试，不当成管理员退出。
