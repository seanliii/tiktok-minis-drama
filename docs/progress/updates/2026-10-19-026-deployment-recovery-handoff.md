## 3. 本次恢复演练实际做了什么

```text
香港独立临时目录中的合成业务库
  → 保持 WAL 在线，调用原 backup / verify / restore
  → 单独保存备份成功时返回的清单指纹
  → 通过固定主机身份的 SSH/SCP 取回备份及指纹
  → Mac 上调用原 verify / restore，恢复到全新目录
  → 独立核对订单、权益、环境、资产路径与文件 SHA-256
```

两端均使用 Node `22.23.2`。香港与本机的原备份工具、数据库结构文件指纹一致，没有为 Linux 临时换另一套实现。

| 核对内容 | 实际结果 |
| --- | --- |
| 香港在线备份、校验、恢复 | 原工具三步均退出 `0` |
| 源库保护 | 连接仍打开时，main／WAL 字节及五类源会话均未改变 |
| 跨主机传输 | 备份和独立成功指纹实际由香港取回 Mac，不是仅在同机复制 |
| Mac 校验、恢复及独立核对 | 均退出 `0` |
| 代表性业务样本 | 2 个假用户、1 笔合成 JPY 已付单集订单、1 条观看权益、2 个资产引用保留 |
| 路径与文件 | 恢复后的绝对资产路径、长度和 SHA-256 符合预期 |
| 短期授权 | 备份及恢复中的五类会话／下载授权清空，已知合成令牌字节没有残留 |
| 原正式环境 | 演练后仍未启用，正式数据库仍不存在，HTTP 仍为 `503` |

**边界必须保留：**

- 样本从一开始就明确标记为合成 `production` 演练，不是把真实生产库改成测试库。
- 视频样本只是校验文件搬运的测试字节，不能据此声称播放器或真实片源已经恢复。
- 假加密字段的保留，不等于正式平台令牌或真实加密密钥已经完成灾难恢复。
- 正常关闭合成连接后可能进行 SQLite 检查点；源 main／WAL 不变证据取自连接仍打开、三步操作完成后的检查。
- 尚未启用**定期加密离机备份、失败告警或真实用户数据恢复验收**。这些要在生产初始化后完成，不能被本次演练替代。

使用与恢复边界见[备份恢复手册](/guide/backup-restore)。
