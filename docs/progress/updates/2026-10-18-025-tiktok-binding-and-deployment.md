## 1. 不再重复要求负责人登录

BytePlus 已通过精确的 Chrome 进程／标签连接正常操作。TikTok 开发者网站在本机直连超时，但从本项目香港主机能够访问。

为继续核查，建立了只监听本机的加密连接，并使用本项目独立的浏览器配置。**没有改变日常 Chrome 的全局代理设置，也没有借用其他项目的云账号或浏览器资料。**

通过已授权的开发者账号登录后，确认页面属于 Aurora；本应用的 Client Key 与项目配置一致，Client Secret 已保存到私有配置，并在页面重新隐藏。没有将开发者登录密码当成 API 密钥。

## 2. TikTok 绑定使用独立身份

为避免将后台上传签发者的密钥交给外部平台，单独创建了绑定身份：

- 不启用控制台登录。
- 仅能读取指定柔佛视频空间的媒体信息和播放信息。
- 不授予上传角色代入、删除、发布、服务器管理或账务权限。
- 先实测读取本项目测试视频成功；代入上传角色被云端明确拒绝。
- 再将该身份用于 Aurora 的 BytePlus 绑定。

提交后，目标账号出现在绑定列表，状态为**已绑定**；刷新并重新打开账号管理后再次确认。平台只展示脱敏 AK／SK。

**绑定确认不等于所有媒资 API、播放器或收费已经通过验收。** 后续仍以实际调用结果为准，不因绑定成功而把权限扩大成全局管理员。

## 3. 修复第二个真实接口差异：令牌中的星号

香港服务器调用官方 OAuth 接口时，收到有效的 `Bearer` 令牌及有效期。真实令牌包含星号 `*`，但之前媒体客户端的字符检查不接受它，导致在发出媒体请求前错误地返回 `MEDIA_TOKEN_UNAVAILABLE`。

本次只调整了这一处字符检查：

- 接受平台真实返回的星号。
- 原样传递令牌，不删除星号或进行 URL 编码。
- 继续校验 `Bearer` 类型、有效期，拒绝空白、控制字符及其他非法字符。
- 不改业务自有的 64 位随机会话令牌格式，不放宽无关的账户验证。

测试使用人工构造的假令牌，没有把真实令牌放进代码或测试：

1. 新增正常格式测试后，旧实现按预期失败。
2. 修复后，媒体客户端 **223 项测试通过**。
3. 同时新增 6 项非法字符检查，覆盖空格、制表符、换行、逗号、引号和非 ASCII 字符。

修复后的完整隔离回归也已执行：**退出码 0，失败 0、跳过 0**，约 358 秒。服务端测试为 1820 项；各运行器通过数汇总为 2367（包含父测试项，不等同于独立业务场景数）。被测副本与当前源码指纹一致，没有使用或改写原业务数据库。

这修复了本地误拒绝问题；**不能据此声称下游视频查询已经成功**。
