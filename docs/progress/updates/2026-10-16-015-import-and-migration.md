## 1. 云视频现在能进入本地后台管理

此前直传只能保留“云端已核验”的任务，运营还不能从该任务建立可管理单集。现在流程是：

```text
选 MP4 → 官方 SDK 直传 → 后端核验 BytePlus 和 TikTok
       → 明确点击“导入为草稿单集”
       → 剧目管理中编辑标题、字幕、集号
       → 后续 TikTok 剧集登记、审核、上架与播放验收
```

- 导入参数只有原任务 ID、本地剧目版本和明确确认；VID、时长、标题、集号来自服务端已核验记录。
- 单集、导入记录、版本更新和审计在同一数据库事务内完成；失败不留下半个单集。
- 重复点击、并发请求或响应丢失后的重试，只返回同一个本地单集，不重复创建。
- 导入后没有 TikTok `episode_id`，不会伪装为已上架或已付款可看。
- 同步平台剧目时额外核对已导入 VID 与上传目标，不能只凭“第 1 集”就换成另一部视频。

操作见[云上传手册](/guide/cloud-upload)。

## 2. 复核发现的问题也已纳入修复

| 问题 | 处理 |
| --- | --- |
| 导入后改集号，旧任务仍占着已经空出的原集号 | 保留原始上传目标，另用可释放的预留集号与唯一索引；导入后由实际单集的唯一集号负责占用 |
| 另一管理员删除导入单集后无法补传 | 不要求先取得原管理员的旧任务权限；空集号可创建新任务，历史仍保留 |
| 超过 100 条任务被静默截断 | 增加固定游标分页；状态变化不会使任务在分页中被跳过 |
| 另一标签页换账号后旧页面还显示前一管理员的文件 | 配置、任务列表及分页核对当前管理员；身份变化清理旧行和上传会话 |
| 成功说明被当作红色错误 | 区分服务端错误与核验／导入成功说明 |

这些修改不开放普通用户访问后台，也没有放宽真实发布、付款、版权或云端归属检查。

```text
/Users/xuan/Desktop/cursor/tiktok/app/tt-minis/scripts/data-backup.mjs
```

它提供备份、校验和恢复：

- SQLite 生成事务一致快照，结合快照内资产清单复制文件，不手工拼凑活跃数据库与 WAL。
- 每个文件核对大小与 SHA-256；清单指纹须独立保存。
- 只恢复到尚不存在的新目录；保留 `local/staging/production` 环境，重写资产绝对路径，不能把测试库变成正式库。
- 不搬浏览器 Cookie、业务登录会话、`.env` 或管理员明文密码；原数据库的登录状态不受影响。
- 这不是 BytePlus 视频云远端文件备份，也不是 Codex 对话导出。目录权限不是加密，跨机传输须用受控方式。

**本轮已经对本机现有业务数据实际执行备份、校验和换目录恢复。** 恢复后使用原管理员重新登录，读取管理片库、封面／字幕和云任务 API；用户、资产、剧目、单集、订单、权益及观看记录数量一致，原库会话数量未变化。
