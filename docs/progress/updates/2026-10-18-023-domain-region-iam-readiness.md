# 023 · 域名、机房与 IAM：现在做到哪里

目标仍然是 **Aurora Drama，日本首发**，不操作旧 DramaVerseJP 或美国应用。

**本轮没有购买主机、注册域名、开通额外套餐或执行真实用户扣费。** 已获得继续实施授权，负责人也已确认完成登录；但开发工具尚未接上同一管理会话。不能用不真实的注册人资料、另一个未登录浏览器或测试配置替代正式条件。

<!-- more -->

## 1. 域名：不再采用加 s 的方案

已按负责人要求排除品牌词尾增加 `s` 的方案。通过 IANA 提供的 RDAP 服务入口，向对应注册局查询了原名和替代名称，并核对注册商公开的首年、续费价格。

- 已有注册记录的名称，不当作可以正常新注册。
- 注册局返回“没有记录”，只是初筛结果；还要确认注册商能否出售、是否为溢价域名以及最终订单价格。
- 不把首年促销价当作第二年续费价。
- **尚未购得的具体候选名、订单草稿和注册人信息仅留在私有交接中**，不提前发布到公开网站。

负责人已从备选中确定品牌域名，不再反复选择。尚未设置生产域名，也没有把未注册的域名填入 TikTok 白名单；购买成功仍以订单和注册状态为准。

## 2. 已确定：BytePlus 香港

**负责人已明确选择 BytePlus 香港，ECS 地域为 `cn-hongkong`。** API、数据库和运营后台按这一选择继续准备，不再要求提供 AWS 或阿里云账号，也不再按此前东京建议采购。

**视频空间仍保留在原来的柔佛区 `ap-southeast-1`。** 业务主机地域和 VOD 空间地域不是同一个配置，不能因为选了香港主机，就把 `BYTEPLUS_VOD_REGION` 改为 `cn-hongkong`。

东京／AWS 的说明属于此前比较方案，不是当前执行决定。此前的香港控制台报价也只是未提交参考，需在可操作的管理会话中重新核对库存、磁盘、网络、备份和最终费用；**未取得订单或资源回执前，不标记为已购买**。

香港服务日本用户的实际登录、首屏、播放鉴权和购买解锁效果仍需日本网络与真机验收。不能凭机房名称承诺具体延迟，也不因选香港就宣称视频一定卡顿或一定流畅。不为未开放市场先购买多套主机。

完整当前部署说明见[云部署手册](/guide/cloud-deployment)。旧文档中“云上传／订阅仍未开发”的早期判断，不再代表当前代码。

## 3. IAM：这次有真实接口结果

**北京时间 2026-10-18 21:31**，在负责人表示登录完成后，使用现有专用服务账号重新通过官方 STS SDK 调用目标上传角色的 `AssumeRole`，仍返回 **`AccessDenied`**。首次 10:22 的探测也被拒绝；登录管理控制台不会自动给服务账号增加 IAM 权限。

这个结果确认：**该账号当前没有成功取得所需的临时上传权限。** 它不能单独区分角色未创建、信任关系未配置或授权策略缺失；这些仍需进入主账号控制台回查。不得把“本地 JSON 结构检查通过”写成云权限已经生效。

负责人已确认完成网页登录；但当前自动化工具仍看到另一个独立浏览器的旧登录／拼图页面，尚未接上负责人使用的管理会话。**这是操作通道尚未接通，不能继续笼统归因于“负责人还没登录”，也不能要求在错误窗口反复验证。** 本轮没有代解验证、绕过验证、提交错误策略或扩大为全局管理员权限。

负责人**不需要学习 IAM 或自己写策略，也无需重复已完成的登录**。先由开发排查正确的浏览器操作入口；取得同一管理会话后继续：

1. 正常录入并回查限定空间的上传策略。
2. 创建只信任专用服务用户的上传角色。
3. 给后台签发者授予指定角色的代入权限及所需媒体核验权限。
4. 重跑真实 STS 检查，再进行私有测试视频上传与服务端核验。

此前已创建的私有视频空间继续保留；本轮没有重新创建或改成公开访问。

## 4. 已准备的交付物

- **私有源码交接包**：从当前已提交代码导出，包含 194 个受版本管理的应用文件，附逐文件及压缩包 SHA-256；检查未包含真实 `.env`、密钥、业务数据库、浏览器会话或 `node_modules`。
- **自生成上传测试素材**：5 秒、720×1280、H.264／AAC 的竖屏测试图案，配套封面和日文 VTT。没有使用外部商业影片或音频。
- 上述素材仅用于私有技术验收，**不是获授权的日本短剧片库**，没有上传到云、公开发布或售卖。
- 预发布／生产配置检查明确指出真实环境文件尚不存在；没有为获得“检查通过”而填入假密钥或关闭保护。

源码包可用于后续目标主机安装和构建，**不等于已经通过 Linux 部署验收**。当前主机上的 Docker 服务不可用，历史虚拟机启动失败也发生在应用测试之前；本轮没有把同一失败反复重跑，也没有把工具问题当作应用故障。

各运行器报告通过数相加为 2359，其中 Node 的统计包括父测试项，**不把这个数解释成 2359 个独立业务场景**。测试覆盖了本地上传、注册、付款解锁、重新登录和退款撤权，但外部平台仍使用隔离替身。

WebKit 跨站 Cookie 测试实际记录了 Cookie 未保存；这是被如实记录的浏览器行为，不是“所有跨站登录都可用”。Minis 的无第三方 Cookie 会话路径另有通过测试，仍需要 TikTok 真机验证。

同轮预发布与生产启动检查均返回 **退出码 1：缺少实际 `.env.staging`／`.env.production`**；真实 STS 也仍为 `AccessDenied`。不能用应用回归通过覆盖这两类未完成条件。

无论本地回归结果如何，以下项目仍必须在真实条件下单独验收：

- 目标 Linux 主机的安装、启动、HTTPS、健康检查及独立备份恢复。
- BytePlus 临时授权、实际文件上传、指定空间核验和 TikTok 可见性。
- 日本 iOS／Android 中的登录、播放、购买、续费、取消、退款和恢复。
- 官方 Sandbox 与生产环境的区别，不能由本地模拟服务替代。
