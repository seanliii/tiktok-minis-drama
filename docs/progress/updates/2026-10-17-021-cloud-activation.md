本记录仅适用于 **Aurora Drama（`7670022867891177493`）日本首发**，不操作旧 DramaVerseJP 或美国项目。

负责人确认付款方式已绑定，并在明确说明操作范围后回复“同意”。本轮执行的是 **VOD 按量服务开通**和 **ECS 标准跨服务角色授权**，不是购买服务器，也不是开放观众付费。

企业认证／合作合同是否全部完成，应以相应状态和平台要求为准。付款方式和 VOD 可用**不能替代企业认证、TikTok 短剧合作合同或优惠价格确认**。

## 2. 视频空间和上传权限准备到哪一步

VOD 的 Spaces 页面仍为空。已经准备以下**未提交**的空间表单：

- 项目：`default`；
- 空间：`auroradrama-jp`；
- 区域：`ap-southeast-1`，本次控制台标为 **Asia Pacific (Johor)**；
- 用途：Aurora 日本首发的专用剧集素材。

控制台提示空间名称和区域在创建后不能修改。区域选择中还出现 `ap-singapore-1`；本轮没有在那里创建第二套空间，也没有把视频区域等同于服务器区域。

下一步按已实现的[云上传方案](/guide/cloud-upload)操作：

1. 确认后创建专用空间，**上传任何片源前关闭自动发布，并核实原片访问控制**。
2. 给已有后台上传子账号配置必要的角色代入权限及媒体核验权限；上传角色只允许该空间的 `vod:ApplyUploadInfo`、`vod:CommitUploadInfo`。
3. 从真实空间取得 VOD App ID 和相关配置，不用 TikTok App ID 代填。
4. 用限定权限实测，核对上传、空间查询和越权拒绝；没有权限时先查原因，不扩大成整个云账号的管理员权限。
5. 完成 TikTok 绑定后，再跑“上传 → 双方核验 VID → 导入草稿 → 平台登记／审核 → 官方播放器”。

**空间创建、上传角色／权限和原片设置尚未提交。** 现有长期密钥没有在本轮输出、公开或提交给 TikTok；目前不能声称后台已经能往真实 BytePlus 空间上传。

## 3. TikTok 绑定不能与后台上传身份混用

重新进入 Aurora 的“行业解决方案 → 管理账号”后，确认：

- 媒体资产管理：**已激活**；
- BytePlus 账号列表：**未绑定**；
- 绑定需要账号 ID、AK 和 SK；
- 绑定弹窗明确说明：验证后 TikTok 会保存 AK/SK，用于访问和管理 BytePlus 内容。

因此，后台用于签发短期上传权限的身份，与交给 TikTok 的媒体接入身份应分开管理。**本轮没有在绑定表单填写或传送密钥，也没有新建第二套长期密钥。** 下一步应先核实平台接入所需权限，再以专用身份完成明确授权；不把主账号密钥或带账务／服务器权限的身份交过去。

本次实际打开的 [TikTok 官方媒体资产指南](https://developers.tiktok.com/docs/en/media-asset-management) 还说明：

- 同一部剧的全部视频必须在同一 BytePlus 账号的同一空间；
- AK/SK 更新后需要在 TikTok 重新验证，否则会影响媒资接口和播放；
- 内容审核通过但未上架仍不能播放，不能用原片地址绕过官方播放控制；
- 多语字幕要求中提到需包含英文。正式提交日文内容前还需核对目标接口的字幕格式和语言要求，不能只准备片源就当作已具备送审材料。
