## 2. 服务器能用 BytePlus，但地域要分别核对

2026-10-16 读取 BytePlus ECS 官方 **Regions and availability zones** 页面，列表包含北京、上海、广州、香港、柔佛和雅加达；**该公开列表未列东京、首尔或新加坡**。其中 ECS 的 `ap-southeast-1` 标注为 **Johor（柔佛）**。[S1]

这是公开文档的范围，不是“这些区域本账号一定能买”的库存承诺，也不推断未来或专属合同下没有其他区域。当前账号尚停在 ECS 服务授权前，未取得本账号真实购买报价。**VOD 空间地域、CDN 覆盖与 ECS 可购买地域不是同一份名单，不要互相套用名称或 region ID。**

建议按两个方案评估：

- **优先一家云管理**：BytePlus ECS 与 VOD 可作为组合候选。业务主机先比较实际可购买的香港／柔佛等区域，在日本真机测登录、片库和订单接口，再决定；不直接承诺日韩线路效果。
- **优先日本业务接口的本地部署**：保留东京业务服务器＋BytePlus 视频的方案。业务服务器不必和视频云同厂商；上一份阿里云东京建议不代表存在“BytePlus 东京”同款机器。

在线联调／小流量阶段仍以 **1 台普通 CPU 主机、4 vCPU／8 GiB、持久化磁盘和独立备份**作为待报价起点；不是容量压测或高可用结论。不买 GPU，不先买多地域主机、Kubernetes 或大额固定视频带宽。实际型号、价格、磁盘和网络费用待购买页与合同确认，不移用其他厂商报价。

## 3. 视频走 BytePlus，要走短剧接入流程

TikTok 官方说明，BytePlus 承担视频托管，开发者平台负责绑定、审核与上架，用户端必须按平台指定方式接入播放器。文档还要求提前完成 BytePlus 合作合同与账号开通，短剧业务可联系 BytePlus 确认对应方案。[S2]

因此，不先自行采购一套不确定适用的普通播放器／CDN 套餐，也不把注册普通账号等同于短剧合同已经完成。应让商务确认是否已有合同、可用空间和短剧计费安排。

```text
运营管理网页
  ├─ 业务后端：剧目、集数、版权确认、上传任务与临时授权
  └─ 浏览器直接上传到 BytePlus VOD
       → 后端核验视频归属
       → TikTok 剧目／剧集登记、审核、上架
       → Minis 官方播放器播放

Minis 用户端
  → 业务后端：TikTok 身份、订单、通知验签、已购权益与观看记录
```

上图是目标业务流程，不表示每个环节已在真实云端验收。视频文件直接由视频云分发，不经业务主机中转；是否允许某个用户观看，则由业务权益和平台内容状态共同判断。不能用公开 MP4 地址绕过审核与播放控制。

## 4. 除认证和账务外，还缺什么

### 团队提供或确认

1. **企业证件**：与当前公司一致的有效商业登记／公司注册文件；使用证件上的名称、注册号和地址。当前上传控件支持 JPG、JPEG、PNG、BMP、PDF，最多 3 个文件、每个不超过 5 MB。
2. **商务／财务安排**：确认短剧 VOD 合同、服务开通和费用口径；如果不使用卡，先让 BytePlus 确认该账号及目标产品能否走其他结算方式，不承诺现已支持。
3. **应用资料**：真正的 Apple Team ID、Aurora 联系邮箱验证、域名权属确认与负责人的审核声明。Apple Team ID 是 Apple 分配的 10 字符标识，不是邮箱。[S3]
4. **域名和内容**：受控域名／DNS 配置权限，以及可用于日本测试、版权明确的视频和字幕。

### 开发继续完成

1. 已有云上传代码使用真实测试空间验收；专用上传角色、AK/SK 只放受控服务端配置，核对空间原片访问控制，不新增全权限账号来代替排错。
2. BytePlus 与 Aurora 绑定后，完成**新建云端剧目、剧集映射、日语及审核字幕要求**的真实接入；文件上传成功不等于剧目已经创建或上线。
3. 部署 HTTPS API／管理页、持久数据、备份恢复和日志告警；更新 Minis 的实际 API 地址、信任域名与支付通知地址，再重新构建对应前端包。
4. 真机验收登录、播放、购买取消／成功、通知延迟／重复、退款与权限隔离。
5. 正式 VIP 的完整续费、到期和退款权益同步仍需开发及平台验证；首发如未完成，就不开放销售，不能用测试 VIP 顶替。

**BytePlus 的云账单与观众在 TikTok 里的付款是两件事。** 绑好云服务付款方式，不代表用户付费已经开通或测试通过。
