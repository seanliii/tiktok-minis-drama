## 已修复的实际问题

| 原问题 | 当前处理 |
| --- | --- |
| 普通浏览器有 SDK 就被当成端内，首页一直等登录 | 无阻塞访客浏览；网页预览不加载平台 SDK，不伪造身份 |
| 选第2集只有地址变化，标题与内容仍是第1集 | 集号、当前选集、媒体元素均跟随路由更新 |
| 图片＋定时器被包装成播放器 | 预览使用本地 CC0 视频与真实播放事件；正式包没有测试视频替代路径 |
| 付费集直达地址没有访问限制 | 显示待解锁与不可购买状态，不在前端自行发放权益 |
| 默认余额120、购买数3、订阅后直接VIP | 删除虚构资产；支付与订阅未开放，不显示假成功 |
| 收藏、历史、设置和客服入口只写开发中 | 收藏／续看接本机存储，设置提供条款／隐私，客服有明确入口 |
| 日文界面混中文、误导价格、假评分与播放量 | 统一关键日文文案，测试内容标识明确，不展示伪造业务指标 |
| SDK 调用签名、取消／失败／无回调处理不完整 | 对照官方 SDK 回调契约修复，有限等待，无 SDK 时不降级成成功 |
| 空链接白屏、视频失败无恢复、弹窗键盘能点到背后 | 缺页返回入口、加载／播放中断流重试、弹窗焦点控制 |
| 构建工具新旧混用 | 使用当前官方 `tiktok-minis-cli@0.0.7`，预览包与平台包分目录 |

## 验证范围

- 单元测试覆盖 SDK、访客状态、本机数据验证与持久化。
- 浏览器用例覆盖首页、搜索、详情、免费与锁定集、收藏、历史、真实媒体播放／恢复／下一集、无网络、缺页、键盘与小屏幕。
- Chromium、WebKit 使用日语环境；WebKit 是本机 macOS 14 可用的兼容构建，**不等于最新 iOS 真机通过**。
- 用真实 HTTP 部分视频响应模拟断流；Chromium 验证已播放后停滞，WebKit 还覆盖等待缓冲完成前的超时。没有仅触发一个假的 `ended` 事件就宣称媒体流程通过。
- 构建与审计分别验证；工具通过不等于端内、内容审核或商业流程通过。
