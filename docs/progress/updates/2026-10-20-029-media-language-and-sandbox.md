## 1. 日语字段究竟怎么填

真实调用给出的结果：

1. 数字 `3` 被拒绝，提示类型不正确。
2. 字符串 **`"ja"`** 通过语言校验，平台继续提示缺少内容标签。
3. `"ja"` 配合仅用于私有技术测试的标签，成功创建平台剧集版本；再次查询可以得到单集信息。

因此，这是字段类型和接口约定问题，不是“日语很难开发”。语言字段相当于给内容贴上“日语”标签；它仍需如实填写，但**已经不是当前需要负责人解决的障碍，也不再依赖技术支持回信**。

测试使用的标签不代表真实商业内容分类，不能照搬到正式片库。

## 2. 从上传到平台登记，修复了哪两步

**上传到 BytePlus 不等于已进入 TikTok 剧集目录。** 官方 SDK 上传成功后，还须用已有 VID 登记到平台；不需要把同一视频再次上传或改为公开下载。

此外，不指定版本的剧集查询可能只返回索引；**指定版本查询**才可用于确认单集详情。后台已接入登记、查询、旧回执恢复及结果不明时先查询的处理，避免重复上传或创建。

## 3. 付款现在到哪一步

正式站继续关闭收费。独立官方支付测试环境已部署在同品牌域名的 `/sandbox/` 路径，使用另一进程、Linux 身份、数据库、加密密钥及浏览器收藏键。

- 正式入口不因沙箱测试而开启真实购买。
- 测试页面不携带正式 Cookie，反向代理也移除沙箱请求和响应的 Cookie。
- 正式回调先校验签名及应用身份，仅将明确标记为沙箱的交易／订阅通知转到测试服务；测试服务再次验签。
- 已完成平台 Test URL 返回 HTTP 200，以及“测试服务记账后确认丢失，重送不重复发权”的合成回归。
- 同域路径分隔**不是独立浏览器 origin 的安全隔离**，不能夸大其效果。

**Test URL 成功不等于发生了订单。** 本阶段最后一次数据库只读检查中，真实 TikTok 用户、订单和订阅通知仍为零。

平台已有授权测试账号，不用重复绑定；**预览版本 6 仅供官方支付沙箱测试，绝不能发布为正式应用**。版本 5 是仍关闭收费的正式配置预览。真机登录、购买、续费、取消、退款和观看权益还需逐项验收；没有用模拟结果替代这些步骤。
