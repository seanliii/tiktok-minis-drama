## 2. 本轮回归发现并处理的问题

### 管理员通知区保留旧记录

旧通知组件屏蔽了 401。管理员会话过期后，只刷新该区不会触发统一退出，原来的用户关联与通知记录还留在页面上。

两处组件恢复公共 API 的会话失效通知，并加了“先显示记录 → 仅通知接口返回 401 → 登录页出现、旧记录和导航消失”的浏览器回归。
普通网络失败仍可局部重试，没有把 503 当作登录失效。

### 旧 SDK 测试没有模拟登录

完整回归首次在全栈阶段出现 **28 项失败、14 项通过**。浏览器截图显示缺少 SDK `login`，不能把这批失败写成通过。
现有测试只模拟播放器和付款；新会话流程还需要一次性 code、无 Cookie 登录引导以及业务令牌。已补这部分边界，并增加真实请求头与不重复换码检查，没有跳过业务登录或放宽生产权限。

### 首次登录提前宣布初始化完成

补齐外部模拟后，trace 又显示登录、账号和剧目接口均返回 200，页面仍报作品不存在。
原因是换码刚完成就设置初始化标志，播放器的身份监听重复开始读取；后续账号核对清理片库，让这次结果被丢弃。

确定性的回归先延迟真实 `/auth/me` 响应，确认旧代码会提前设置标志；修复把完整初始化完成保留在刷新／显式授权流程结束时，不移除换号后清理旧数据的检查。

### 同一账户自动续期误清片库

继续检查后，又用真实 HTTP 和 SQLite 复现了四种情况：客户端到期／服务端到期，分别读取目录／详情。用户和权益没有变化，接口返回有效 200，但目录空白、详情返回空值。

修复区分三种情况：

- **只更新凭据**：账户、实际权益不变，不打断正在读取的片库。
- **权益真的改变**：仍清理旧片库；同一账户的目录／详情最多重新 GET 一次，取得更新后的数据，不强行接收原失效结果。
- **退出或换号**：保持原有隔离，不替新账户重放旧读取，更不重复执行支付等写请求。

新增永久回归先得到 **8 项失败、30 项通过**；修复后完整前端单测为 **172 项通过**。其中包括真实本地 VIP 购买后续期读取，以及迟到响应不能跨账号的反例。

### 生产路径测试要跟随真实登录流程

测试原来等“登录”按钮，但页面已经完成静默登录；本地 sandbox 的 SDK 替身还错误宣称自己运行在 Minis 内。已让测试从实际页面响应获取当前业务会话，并正确区分本地浏览器与平台环境。

退出检查等待真实退出响应及登录页出现，不在退出尚未完成时把旧令牌的 401 当作最终页面状态。没有注入页面账号、直接写数据库发权，或将真实 API 响应替换成成功。
